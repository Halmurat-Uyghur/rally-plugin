## Findings

### 1. [P1] Preserve external-image blocking for malformed tags Swing accepts

**Location:** [RallyHtmlUtils.kt, lines 166–167](https://github.com/Halmurat-Uyghur/rally-plugin/blob/4ee34152b4507422668e24f820ea98d25cb9027e/src/main/kotlin/com/github/halmurat/rally/util/RallyHtmlUtils.kt#L166), using `TAG_PATTERN` at line 50. The new pass replaces the previous whole-input external-source neutralizer in `RallyDetailPanel.wrapHtml()`.

**Trigger:** a stored description contains an image tag with a quoted external source and an unmatched apostrophe elsewhere in the tag, for example:

```html
<img src="http://evil.invalid/unique-pixel.png" alt=Bob's>
```

`TAG_PATTERN` requires balanced quoted portions. It therefore skips this entire tag, and `NON_DATA_SRC` never examines its source. Swing's HTML parser is more permissive: it accepts the image and retains the external URL. Opening the description can consequently cause the IDE to fetch an arbitrary URL from the developer's machine. This bypasses the API client's host checks because Swing performs the image load itself.

**Confirmed regression:** a headless `JTextPane` rendering probe compared the base sanitizer with the PR head. A custom HTTP URL handler recorded fetch attempts and returned an in-memory PNG; no real external request was made.

```text
Base sanitized: <img src="" alt=Bob's>
Head sanitized: <img src="http://evil.invalid/unique-pixel.png" alt=Bob's>
Base fetches:   []
Head fetches:   [http://evil.invalid/unique-pixel.png]
```

The base's global external-source pattern blocked this same input even though its HTML was malformed. The new tag-scoped pass removes that protection. This finding establishes an unsolicited outbound fetch; it does not establish API-key disclosure or code execution.

**Recommended change:** make sanitization account for the HTML that Swing actually accepts, including malformed tags. Prefer a parser-aware allowlist or otherwise retain a conservative final resource-blocking boundary that cannot be skipped by tag recognition failures. A stricter regex alone must not make unrecognized markup implicitly trusted.

**Regression coverage:** render the example through the complete description-cleaning pipeline and assert zero resource fetches. Include unmatched quotes, unquoted attribute values containing apostrophes, and incomplete tags, alongside the existing quoted-angle-bracket cases.

### 2. [P2] Do not treat attribute contents as separate `src` attributes

**Location:** [RallyHtmlUtils.kt, lines 144–145](https://github.com/Halmurat-Uyghur/rally-plugin/blob/4ee34152b4507422668e24f820ea98d25cb9027e/src/main/kotlin/com/github/halmurat/rally/util/RallyHtmlUtils.kt#L144), applied at line 167.

**Trigger:** otherwise valid HTML contains ordinary `src=...` text inside a quoted attribute:

```html
<p title='the src=foo'>Important requirement</p><p>Acceptance criteria</p>
```

`NON_DATA_SRC` scans the whole tag without tracking attribute boundaries. It interprets `src=foo` inside the title as an independent attribute, and its unquoted-value branch also consumes the title's closing apostrophe. The replacement produces:

```html
<p title='the src="">Important requirement</p><p>Acceptance criteria</p>
```

The now-unterminated title absorbs the rest of the markup. The headless Swing rendering probe confirmed that both paragraphs disappear:

```text
Base document text: "\nImportant requirement\nAcceptance criteria"
Head document text: "\n"
```

This is a display regression for valid, non-active content. The stored Rally description is unchanged, but the detail panel can hide its requirements and acceptance criteria.

**Recommended change:** operate on actual parsed attributes, preserving quoted attribute contents. At minimum, the unquoted-value branch must not consume enclosing quotes; that alone does not address the broader attribute-boundary mistake.

**Regression coverage:** assert rendered document text, not just sanitized-string fragments, for the example and for both quote styles. Verify that genuine external `src` attributes are still removed while `src=...` text inside titles remains harmless.

### 3. [P2] Reconcile workspace metadata before the missing-Username return

**Location:** [RallyToolWindowPanel.kt, lines 664–668](https://github.com/Halmurat-Uyghur/rally-plugin/blob/4ee34152b4507422668e24f820ea98d25cb9027e/src/main/kotlin/com/github/halmurat/rally/ui/RallyToolWindowPanel.kt#L664).

The new My Tickets/blank-Username guard exits before `getClient()` and the project/sprint reload logic. This also skips settings reconciliation, although the Create actions still depend on that metadata.

**Reproduction sequence:**

1. Load workspace A so its project and sprint lists are cached.
2. Select My Tickets with Username blank.
3. Change Workspace Ref to B and apply Settings. Clicking Refresh has the same early-return behavior.
4. Open Create → User Story or Defect and choose a project or sprint.

The dialog still offers A's metadata indefinitely. Source tracing confirms the following chain:

- The settings listener only schedules `loadTickets()` (lines 209–213).
- The added return precedes `getClient()` and metadata reload. `showUsernameNeeded()` preserves and re-enables the previously loaded dropdowns (lines 286–297).
- Both create dialogs receive `cachedProjects` and `cachedIterations`, then capture the selected refs (lines 1368–1385 and 1397–1410).
- `executeCreate()` subsequently obtains the client for the new settings (line 1438). Client replacement changes loading flags but cannot replace refs already captured by the dialog.
- `createUserStory()` and `createDefect()` send the supplied `Project` and `Iteration` refs without a Workspace field or URL parameter ([RallyApiClient.kt, lines 1770–1806](https://github.com/Halmurat-Uyghur/rally-plugin/blob/4ee34152b4507422668e24f820ea98d25cb9027e/src/main/kotlin/com/github/halmurat/rally/api/RallyApiClient.kt#L1770)).

The definite consequence is stale choices and submission of stale refs under the newly configured connection. If the same server/key can access both workspaces, an old project can remain the creation target; other configuration changes can cause the request to fail. Backend acceptance was not live-tested. The base version proceeds through client reconciliation and metadata reload, so this persistent stale state is introduced by the new guard.

**Recommended change:** separate the missing-Username restriction on ticket queries from client and metadata reconciliation. Refresh or invalidate metadata when the connection changes, and ensure Create cannot consume lists from a different configuration.

**Regression coverage:** with fake workspaces A and B, apply B while My Tickets has no Username; assert that no ownerless ticket query is sent, that A's choices cease to be usable, and that creation can only submit metadata for B.
